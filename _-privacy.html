SRC-D2 // Privacy Protocol

LAST REVISION: 2026-08-31 // STATUS: ACTIVE ENFORCEMENT

This document establishes the codified evidentiary baseline regarding data access, processing, and retention within the SRC-D2 Integrated Development Environment (IDE) and Dashboard. SRC-D2 operates under a strict Zero-Knowledge Architecture. No proprietary external backend is utilized to harvest, process, or aggregate user data.

I. Local Data Persistence (The Vault)

All operational data, incident logs, projects, and encrypted cryptographic keys are localized entirely to the user's client hardware.

  • Persistent Operator Track: Data is secured using PBKDF2-derived AES-GCM encryption and retained strictly within the browser's localStorage and IndexedDB.
  • Volatile Guest Track: Ephemeral session data is retained in sessionStorage and is permanently destroyed upon tab closure or session termination.
  • Zero Transmission of Vault Data: SRC-D2 does not transmit incident data, project records, encrypted vault contents, or operator credentials to any developer-owned or third-party server for storage. The scratchpad code sandbox's optional remote runners are disclosed separately in Section III; those transmit only the code an operator explicitly chooses to compile, never vault contents.

II. Hardware & Sensor Processing

SRC-D2 requires explicit permission to interface with local hardware sensors. This data is processed in real-time on the client machine and is strictly volatile.

  • Audio DSP (PEACE_OPERATOR): Microphone streams are ingested via the Web Audio API for real-time psychoacoustic and environmental analysis. When the field-recording feature detects a qualifying event (e.g. bird-call detection), a short clip is cut from a rolling local buffer and saved locally to IndexedDB as part of the associated project. Audio is never transmitted over any network — all captured clips remain confined to client-side storage under the same Zero-Knowledge Architecture as the rest of the Vault.
  • Hardware Audit (BLE): The Web Bluetooth API is utilized for local spectrum auditing. MAC addresses and broadcast names are displayed transiently for proximity awareness and are not logged or exported externally.
  • Device Fingerprinting: System metrics (hardware concurrency, battery status, user-agent) are accessed locally to generate hardware profiles for session stability and diagnostic integrity, remaining confined to the client.

III. Third-Party Infrastructure & Telemetry

To execute specific network diagnostics and deliver the application, SRC-D2 interacts with the following external endpoints. All outbound calls are gated by the Network Killswitch (ᚾ) — engaging ᚾ severs every outbound service below without affecting local encryption or vault access.

  • IP Resolution (Net Sentry): The application executes a transient GET request to api.ipify.org to resolve the operator's public IPv4 address for subnet calculations. With the killswitch engaged or the device offline, this falls back to a local device fingerprint and reports it as a local — not public — identifier.
  • Remote Code Execution — Rust / C++ (Piston): The scratchpad's Rust and C++ runners transmit user-authored source code to emkc.org (Piston) for compilation and execution. This code, along with compilation timing and connection IP metadata, is processed by that third party. Only the code an operator explicitly chooses to run is sent; no vault data, project records, or logs accompany it. The killswitch (ᚾ) gates every call and refuses to run while engaged.
  • Python Runtime (Pyodide): The Python runner loads the Pyodide runtime (CPython compiled to WebAssembly) from cdn.jsdelivr.net on first use (~10MB, one time). The CDN receives standard connection telemetry for that fetch. Once loaded, Python executes entirely on-device and runs fully offline with the killswitch engaged. Self-hosting this dependency is supported for fully air-gapped operation.
  • Fonts: The Michroma and Space Mono typefaces are loaded from Google Fonts (fonts.googleapis.com / fonts.gstatic.com) on first render. No data beyond the standard font-request telemetry is exchanged.
  • Hosting Infrastructure: SRC-D2 is hosted via GitHub Pages. GitHub processes connection telemetry (such as visitor IP addresses) as part of infrastructure delivery. Operators are advised to consult the GitHub Privacy Statement.

IV. Operator Autonomy

The operator retains absolute control over their local data. Cryptographic erasure of all stored configurations, encryption keys, and incident databases can be executed instantly via the interface's system reset protocols. The Network Killswitch (ᚾ) provides an additional, instantaneous severance of all outbound services without erasing any local data.
